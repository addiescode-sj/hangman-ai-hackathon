# T1.4 톤수(tonnage) 비교 EDA

스크립트: scratchpad/eda_c/t14.py, t14b.py (train 12,222행 / catalog 78,381행, vessel_id 유일, train 타깃 고유 5,851개, 타깃 중복 비율 약 46%)

## 1. 카탈로그 컬럼 구조
- `size`는 `unit`에 따라 의미가 달라지는 값이다. DWT 51,414행(66%), Passengers 8,077, TEU 6,705, LOA 3,203, HP 2,660, cu.m. 2,374 등 17종이다.
- unit=DWT인 행에서는 size == deadweight_tonnage 가 95.9%다. unit=GT인 64행은 size == gross_tonnage 가 100%다. 그 외 unit은 size가 톤수가 아니다.
- 결측률은 gross_tonnage 0.2%(거의 없음), deadweight_tonnage 6.9%, size 8.1%다. Passengers/cu.ft./Lane m.는 size 결측이 32~44%로 높다.
- train 타깃 12,222행의 unit은 DWT 80%, cu.m. 7%, Cars 6%, TEU 5%다. 일치도는 gross_tonnage 기준으로 보면 된다.

## 2. train vs catalog 톤수 (타깃 조인, train 톤수 존재 11,429행)
| 비교쌍 | 정확일치 | 오차 p50/p90/p95/p99 | 1% 이내 | 5% 이내 | 10% 이내 | 50% 초과 |
|---|---|---|---|---|---|---|
| train GT - cat GT | 52.6% | 0 / 4.6% / 4.9% / 11.6% | 59.3% | 97.7% | 98.8% | 0.01% |
| train 국제GT - cat GT | 53.7% | 0 / 4.5% / 4.8% / 5.0% | 60.4% | 99.0% | 100% | 0% |
| train GT - cat DWT | 0% | 39% / 49% / 170% / 256% | 0.3% | 1.6% | 4.2% | 8.0% |
| train GT - size(DWT 단위) | 0% | 40% / 47% | - | - | - | - |

- 정답 쌍은 catalog gross_tonnage와 train gross_tonnage(또는 international_gross_tonnage)다. DWT와 size는 train 톤수와 무관해서 쓸 수 없다.
- train GT와 국제GT는 92.2%의 행에서 같다. 국제GT 쪽이 오차가 조금 더 작아서(99.0% vs 97.7%가 5% 이내) 국제GT를 우선하고 GT를 보조로 쓰면 된다.
- 오차 구조는 이분 구조다. 약 54%는 완전일치(오차 0)이고, 나머지 약 45%는 부호 무관하게 약 3.5~5%(최대 약 6.3%) 어긋난다. 0.1% 이내는 54.5%뿐이고 0.1%~3% 구간은 거의 비어 있다. 이는 카탈로그 GT에 약 ±5% 노이즈를 일부러 섞은 것으로 보인다. 부호는 대칭이다(음수 48.9%).
- 5%를 넘는 외곽값은 약 1.2%(135행)이고, 대부분 train GT가 catalog GT보다 20~30% 작은 소형 DWT 선박이다. 50% 초과는 1건뿐이다.
- 연도 의존성은 없다. 연도별 정확일치율은 0.50~0.56이고 10% 초과율은 0.5~2%다.
- vessel_type별 정확일치율은 0.46(풀컨테이너선)~0.65(케미칼가스)로 뚜렷한 차이가 없다. 케미칼 운반선만 10% 초과율이 4.2%로 높고, 나머지는 1.5% 이하다.
- 결측: train 톤수 결측은 6.5%(793행)다. 그 행의 타깃은 catalog GT가 100% 있다(역방향 결측은 0건). 같은 타깃의 train 행끼리 GT가 다른 경우는 4.8%다.

## 3. 톤수 단독 변별력 (train 톤수 있는 행 3,000개 샘플)
| 윈도우 | 타깃 포함률(recall) | 후보 수 median / mean / p90 |
|---|---|---|
| 정확일치(0) | 52.5% | 2 / 6.9 / 11 |
| 0.5% | 57.1% | 120 / 173 / 392 |
| 1% | 58.5% | 241 / 322 / 681 |
| 5% | 95.5% | 1,188 / 1,411 / 2,544 |
| 6% | 98.3% | 1,451 / 1,670 / 2,888 |

- 정확일치 후보는 중앙값 2개뿐이라 매우 강한 필터다. 다만 정답의 52%만 담고, 정확일치 후보가 0개인 행이 약 30%다(톤수가 노이즈로 섞였거나 카탈로그에 없는 값).
- 순위: 동률을 불리하게 세면 타깃이 상위 1위 5%, 10위 44%, 100위 56%, 1000위 81%이고 중앙 순위는 20위다. 정확일치 행만 앞서고 노이즈 행은 수백~수천 위로 밀린다.
- 톤수만으로는 1순위를 정할 수 없다. 이름/호출부호/선종/국기와 함께 쓰는 보조 신호로 가치가 있다.

## 4. 시사점 및 후보 생성 규칙
1. 톤수 점수는 이진 + 완만한 감쇠로 설계한다. `ref = international_gross_tonnage`(없으면 gross_tonnage), `d = |cat.gross_tonnage - ref| / ref`.
   - d == 0: 강한 가점(정답의 약 53%가 해당, 우연히 일치할 후보는 평균 약 7개).
   - 0 < d <= 0.05: 약한 가점. 실제 정답의 약 43%가 3.5~5%에 몰려 있으므로 이 구간 안에서는 d가 작아도 이득이 거의 없다(평탄하게 처리).
   - d > 0.065: 하드 필터 대신 큰 감점. 정답 이탈은 약 1.7%뿐이다.
2. 후보 생성의 하드 필터는 `d <= 0.065`(recall 약 98.5%)로 하되, 후보가 평균 약 1,700개로 크므로 이름/호출부호 블로킹을 먼저 하고 톤수는 재정렬 단계에서 쓴다. 톤수 단독 블로킹은 권장하지 않는다.
3. train 톤수가 결측(6.5%)이면 톤수 항을 중립(0점)으로 두고 감점하지 않는다.
4. DWT, size는 쓰지 않는다. 선종/단위 정보는 별도 EDA(선종 매핑)에서 다룬다.
5. 연도, vessel_type에 따른 톤수 규칙 분기는 불필요하다.
