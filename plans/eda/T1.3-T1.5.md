# T1.3 / T1.5 이름 노이즈 분류와 동명 선박 모호성

데이터: train 12,222행(고유 target 약 5,851척), catalog 78,595행. 모든 target_vessel_id가 catalog에 존재한다. 스크립트는 scratchpad/eda_b/a.py, b.py에 있다.

## T1.3 이름 노이즈 분류 (train.vessel_name vs 정답 catalog.vessel_name)

| 기준 | 일치율 |
|---|---|
| 원문 완전 일치 | 0.23% (28행). train은 100% 대문자이고 catalog는 Title Case이기 때문이다 |
| 대소문자만 무시 | 약 56.4% (6,892행) |
| 정규화(NFKC, 대문자, 영숫자/한글 외 제거) 후 일치 | 58.4% (7,137행) |
| 정규화 후에도 불일치 | 41.6% (5,085행) |

정규화로 추가 해결되는 233행은 전부 하이픈 같은 구분자 차이다(`STOLT-CEDAR` vs `Stolt Cedar`, `CMA-CGM` vs `CMA CGM`). train 하이픈 이름은 268개, catalog 정답 하이픈 이름은 67개다. 정규화 후 일치한 7,137행은 토큰 열이 모두 같아서 공백 추가/누락 노이즈는 관측되지 않았다.

### 불일치 5,085행의 유형 (전수 규칙 분류 + 샘플 수동 확인 150쌍 이상)

| 유형 | 건수 | 비율(전체) | 예시 (train -> catalog) |
|---|---|---|---|
| 한글 표기 (영문명 음차) | 1,191 | 9.7% | `그랜드 에이스9` -> Grand Ace 9; `월러스 에이스` -> Walrus Ace; `티와이아이리스호` -> TY Iris |
| 1글자 누락(catalog 기준) | 1,284 | 10.5% | `SOUTHRN SHARK` -> Southern Shark; `SV ADELIDE` -> SV Adelaide; `ARDMRE DAUNTLESS` -> Ardmore Dauntless |
| 1글자 추가 | 1,200 | 9.8% | `WOOYANG LEADDER` -> Wooyang Leader; `SAKUURA GAS` -> Sakura Gas; `CHIOS SUNRRISE` -> Chios Sunrise |
| 인접 문자 전치 | 1,088 | 8.9% | `HPC VISOIN` -> HPC Vision; `MTM AMAOZN` -> MTM Amazon; `ATALATNA T` -> Atalanta T |
| 다중 편집 (유사도 0.8 이상) | 252 | 2.1% | `MAESRK MAGELAN` -> Maersk Magellan; `DS PRSPRITY 7` -> DS Prosperity 7; `TORM TIMMOHY` -> Torm Timothy |
| 1글자 치환 | 4 | 0.03% | `OCIOS IOAANIS` -> Ocios Ioannis (같은 쌍의 반복) |
| 접두어 M/V | 53 | 0.4% | `M/V HEMISPHERE` -> Hemisphere; `M/V UNIPOWER` -> Unipower; `M/V SEREN` -> Seren |
| 부분 유사 (선사 접두어 교체) | 4 | 0.03% | `HAFNIA MERLIN` -> BW Merlin; `CX KYTHIRA` -> Clipper Kythira; `SWAN SPIRIT` -> Bay Spirit |
| 완전히 다른 이름 (개명 의심) | 9 | 0.07% | `CENTRAL PARK` -> Caifu Chao; `HAFNIA WREN` -> BW Wren; `FAIRCHEM BRONCO` -> City Island |
| 어순 변경 / 약어 / 잘림 | 0 | 0% | 확인되지 않음 (로마숫자 `Ⅱ`는 NFKC로 해소됨) |

해석:
- 영문 이름 불일치 3,894행 중 약 97%(3,824행)가 편집거리 1~2 이내의 타이핑 오류(누락, 추가, 전치)다. 노이즈는 사실상 "철자 오류 주입"으로 합성된 것으로 보인다.
- 한글 이름은 9.7%이며, 한글 포함 행 중 flag가 대한민국인 비율은 37%뿐이다. 따라서 국적이 한국이라는 단서로 한글 여부를 추정할 수 없다. catalog에는 한글 이름이 0건이므로 음차 역변환이나 한글 -> 로마자 변환이 필요하다. 접미사 `호`는 96건이다.
- 개명 의심 13행(partial 4 + different 9)은 이름만으로는 복구할 수 없고 tonnage/flag/type이 필요하다.

### 타이핑 오류 샘플의 후보 모호성
타이핑 오류 150행을 샘플링해 difflib 유사도로 전체 catalog 고유 이름 중 top-k를 조회했다. 정답이 top1이면 148/150, top3이면 150/150이었고, 1위 점수 동점은 4건이었다. 이름 유사도만으로도 대부분 복구되지만 동점이 있어 보조 필드가 필요하다.

## T1.5 동명(homonym) 모호성

catalog 정규화 이름 기준 (78,283개 고유 이름):

| 공유 선박 수 | 이름 수 |
|---|---|
| 1 | 77,972 |
| 2 | 310 |
| 3 | 1 (HOUEI) |

동명군에 속한 catalog 행은 0.79%(623행)다. 자주 나오는 이름은 SEAGEM, SEAMASTER, NEWSUN, FENGSHUN, AQUAMARINE, NESTORI, EUROSTAR 등이다.

중요 관찰: train 12,222행의 정답 이름은 단 한 건도 동명군에 속하지 않는다. 정답 후보 수는 전부 1이다. 무작위라면 약 1%(100행 안팎)가 걸려야 하므로 train 정답이 유일 이름 선박으로 구성되었을 가능성이 높다(test도 같을 것으로 추정되나 확인 필요). 같은 train 정규화 이름이 서로 다른 target을 가리키는 경우도 0건이다. 또한 target이 중복되는 행이 6,371건이어서 같은 선박이 여러 연도에 반복 등장한다.

동명군 311개(참고, 쿼리 측 모호성이 생길 경우)에서 구분 가능 여부:

| 필드 | 군 전체를 구분하는 비율 |
|---|---|
| gross_tonnage | 309/311 (99.4%) |
| flag | 261/311 (83.9%) |
| deadweight_tonnage | 265/311 (85.2%) |
| vessel_type | 250/311 (80.4%) |
| flag/GT/type 중 하나라도 | 309/311 (99.4%) |

catalog 내에서 이름, flag, GT, type이 전부 같아 구분 불가능한 행은 4행(2개 이름)뿐이다. 단 train의 gross_tonnage는 6.5%가 결측이고, 값이 있어도 정답 catalog GT와 일치하는 비율은 약 49%(international 열 포함 50%)이므로 GT 정확 일치에만 의존하면 안 된다.

## 정규화와 후보 생성에 대한 시사점
1. 정규화는 NFKC, 대문자화, `[^A-Z0-9가-힣]` 제거로 충분하다. 이것만으로 58.4%가 정확 매칭되고 공백 처리는 따로 필요 없다. `M/V ` 접두어 제거를 추가하면 +0.4%다.
2. 나머지 약 30%는 편집거리 1~2의 철자 오류이므로, 문자 n-gram(2~3gram) 또는 deletion-neighborhood 인덱스 기반 퍼지 후보 생성이 필요하다. difflib 유사도 top3 재현율은 샘플에서 100%였다. 전치 보정(Damerau 거리)을 반드시 지원해야 한다(전치가 타이핑 오류의 28%).
3. 한글 이름(9.7%)은 별도 경로가 필요하다: 한글 -> 로마자 변환(국어 로마자 표기와 외래어 음차 규칙을 고려), `호` 접미 제거, 음소 수준 유사도. 한글 행의 flag/type은 후보 필터로 신뢰성이 낮다(37%만 대한민국).
4. 개명 및 선사 접두어 교체(약 0.1%)는 이름 매칭에서 포기하고 GT/type/flag 기반 보조 경로로 처리한다. 상한 손실은 작다.
5. 동명 모호성은 train 기준으로 무시할 수 있는 수준(정답이 전부 유일 이름)이다. 다만 퍼지 매칭 후 동점(샘플 4/150)이 있으므로 동점 해소에 GT, flag, type을 쓰되 train GT 일치율이 49%임을 감안해 하드 필터가 아닌 가중 점수로 쓴다.
6. 검증 시 target_vessel_id 중복(같은 선박이 여러 행)이 있으므로 선박 단위 그룹 분할(GroupKFold)을 사용하지 않으면 이름 암기로 성능이 과대평가될 수 있다.
