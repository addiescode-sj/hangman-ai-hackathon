## T7.1 실험 로그 요약

### 문제 구조 (P0·P1)
- 지표 = 0.7 × 한글명 정확도 + 0.3 × 비한글 정확도. 한글명 행은 9.7%(382척)뿐 → **한글 음역 매칭이 점수의 70%**.
- 검증: StratifiedGroupKFold(그룹=선박, 층=한글) fold 0 고정 holdout = 전부 미등장 선박.
- 이름 노이즈: 비한글은 편집거리 1~2 철자 오류, 한글은 영문명 음차. 톤수는 catalog GT와만 일치(정확 54%, 나머지 ±5%). flag/type은 soft 신호(77%/60%).

### 방법론
1. **음운 골격 키** (`src/normalize.py`): 한글 자모와 영문 철자를 같은 자음 클래스열로 투영 (모음·ㅎ/H 제거, 자음 앞 R 묵음, 연음 C/G, 병음 어두 X→S, 대문자 약어는 알파벳 이름으로). 문자 체계와 무관하게 비교 가능.
2. **후보 합집합** (`src/matcher.py`): 정규화 이름 exact + 3-gram + 톤수 최근접 + 골격 2-gram top-40.
3. **재순위**: sklearn HistGradientBoosting pointwise, 38 피처 (이름·골격·로마자 유사도, 톤수 gap, 학습형 P(flag)/P(type), 카탈로그 결측 prior, 후보집합 상대 피처).
4. 제출: sklearn 1.5.2 클린 venv에서 학습한 pickle + train call_sign 직접 조회(보조 규칙).

### 실패 / 미채택
- 국어 로마자 표기(RR) 단독 매칭: 외래어 역음역에 부정확 (에이스→EISEU) → 골격 + 보조 피처로만 사용.
- 노이즈 증강 학습 (톤수 제거·오타 복제 20%): clean 0.9808→0.9367, 톤수 제거 조건에서도 이득 없음 (plans/P5.md).
- 짧은 영문명 오타(DORET→Dorset 등)와 선사 접두어 교체(HAFNIA WREN→BW Wren)는 후보 미회수 → 이득 ≤0.1%p라 보류.
- LightGBM ranker: 평가 이미지에 없음 → HGB로 대체.

### 남은 위험
- 한글 행의 톤수 결측 시 한글 정확도 0.71 (train 한글 행 결측 0건이라 평가셋에서도 드물 것으로 가정).
- 서버 sklearn이 1.5.2가 아니면 pickle 경고/오류 가능 → 학습 코드(`model/matcher.py` Ranker.fit)가 패키지에 있어 train.csv 동봉 방식으로 전환 가능.
- reflag 선박에서 flag 피처 역효과 (KMTC Seoul 사례).

## T7.2 현장 적용안: Top-N 추천 + 담당자 확인

holdout 실측 (plans/scratch/p7_topk.py):
| 지표 | hangul | non_hangul | weighted |
|---|---|---|---|
| top-1 | 0.9767 | 0.9902 | 0.9808 |
| top-3 | 0.9845 | 0.9907 | 0.9863 (= 후보 recall 상한) |

| 자동 확정 임계값 (모델 점수) | 자동 처리 비율 | 자동 처리 정밀도 |
|---|---|---|
| ≥ 0.5 | 98.2% | 99.96% |
| ≥ 0.9 | 97.8% | 99.96% |

워크플로:
1. 입출항 기록 입력 → 모델 점수 ≥ 0.5 이면 자동 매칭 (98%, 오류 약 1/2,500).
2. 미만이면 상위 3개 후보를 이름·톤수·국적·선종과 함께 담당자에게 제시 → 1클릭 선택 (top-3에 정답 포함률 = 상한).
3. 후보 3개 모두 아니면 수동 검색 → 확정 결과를 call_sign→vessel_id 사전에 누적 (재입항 시 즉시 조회, train에서 call_sign↔선박 1:1).
4. 확정 쌍은 주기적으로 재학습 데이터로 편입 (특히 한글 음역 쌍).
