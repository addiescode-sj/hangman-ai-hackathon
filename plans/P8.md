### 에이전트 M (T8.3, T8.6) — 완료
- T8.3: train/catalog에 혼합명 0건 → 382쌍에서 토큰 하나를 영문으로 바꾼 합성 1,090건으로 평가. 새 키(문자 체계별 구간 분리, 약어 판정 = 대문자 2자 이하 또는 모음 없는 5자 이하)는 골격 일치 0.5798→**0.9266**, 후보 recall 0.9743→**0.9872** (16건 개선, 0건 악화). 순수 한글·영문명 키는 바뀌지 않음(84,441개 assert). 이식용 코드: plans/scratch/p8_mixed/portable_patch.py (자체 테스트 포함).
- T8.6: 유형 C의 한글 행만 1등 답으로 내는 진단(D2)은 C 안의 행 수를 몰라 **식별 불가**. 유형 C를 **모델의 2등 후보로 답하는 진단(D3)**은 점수가 0.7·(2등이 정답이었던 행 수)/H라 식별 가능 (1행 = 0.00233). 권장 순서: ① hangul_all 1등 답(오답 수 e_H) ② e_H≥1이면 hangul_all 2등 답 ③ low_margin 2등 답. 도구: plans/scratch/p8_diag/make_diag.py, 다른 코드베이스가 제공할 지점은 `diag_hook.py`의 `ranked(row)` 하나. 로컬 가짜 test(한글 285행)에서 8개 구성 모두 기대 점수 = 실측, 행 섞기·단독 행 실행 결과 동일.
- 부수 발견 → T8.7 (해시 시드 의존 버그).

### 에이전트 L (T8.1, T8.2) — 중간
- 준비 완료: MPS venv(torch 2.14.1, transformers 4.57.6, peft 0.21.2), kanana-1.5-2.1b 다운로드, 고유 382쌍(fold별 77/77/76/76/76). 이 저장소 후보 recall은 쌍 기준 0.979(8쌍 누락).
- MPS 처리량: LoRA 1개 학습 약 3분, 채점 약 28.5쌍/초.
- T8.2 (CPU, 한글 1,191행): 톤수 ±7% 창 크기 중앙값 1,570 / p90 2,872, 정답 포함 99.33%. ±10% 창은 중앙값 2,074, 정답 포함 **100%**. 후보에는 없고 창에만 있는 정답 26행. 선종 필터(임계 1e-3) 적용 시 ±7% 창 중앙값 565, 포함 0.988.
- L4 비용 추정: 어댑터 1개로 300행 × 565~1,570쌍 = 17만~47만 쌍, 13~70분 → 20분 제한에서 창 전체 채점은 어댑터 1개도 빠듯. 창에서 후보에 없는 것만, 그리고 LLM 최고점이 낮을 때만 채점하는 방식이 현실적.
- LLM 채점 대기열(run_all.sh)은 에이전트 종료와 함께 중단돼 메인 세션에서 재실행 (약 2~2.3시간). 끝나면 evaluate_names.py, eval_window.py 실행.
